# SightPlay — Mobile Viewport Roadmap

Status: ACTIVE  
Phase: Stabilization + Mobile UX Evolution  
Last Updated: 2026-05-25

---

# 1. Vision

SightPlay is evolving into:

> An interactive mobile piano practice workspace.

The application is no longer treated as:
- a standard desktop-first website
- a dashboard interface
- a traditional responsive web app

The notation viewport is becoming the primary experience.

---

# 2. Strategic Direction

Current direction:

Architecture Freeze
→ Stabilization
→ Mobile Viewport Foundation
→ Overlay Controls
→ Immersive Performance Mode
→ Advanced Mobile UX

Renderer evolution is NOT the current priority.

Viewport experience IS the current priority.

---

# 3. Primary UX Goals

## Goals

- maximize notation readability
- improve mobile usability
- support landscape piano usage
- support tablet usage
- reduce UI clutter
- create immersive practice workflow
- preserve renderer stability

---

# 4. Core UX Philosophy

## 4.1 Notation First

Notation viewport is the hero.

Controls are secondary.

---

## 4.2 Overlay-Based Interaction

Controls should eventually become:
- floating
- collapsible
- contextual
- auto-hidden

Inspired by:
- MuseScore mobile
- video player overlays
- digital music readers

---

## 4.3 Landscape First

Landscape mode becomes:
- primary piano practice mode
- primary tablet mode
- primary immersive mode

Portrait remains supported but secondary for long practice sessions.

---

# 5. Mobile UX Phases

---

# PHASE 1 — VIEWPORT FOUNDATION

Goals:
- responsive viewport
- fit-width behavior
- zoom support
- fullscreen support
- orientation support

No renderer modifications.

---

# PHASE 2 — OVERLAY CONTROLS

Goals:
- floating controls
- collapsible panels
- reduced chrome
- contextual UI

---

# PHASE 3 — IMMERSIVE PERFORMANCE MODE

Goals:
- fullscreen notation
- minimal distractions
- piano stand mode
- immersive practice UX

---

# PHASE 4 — ADVANCED MOBILE UX

Goals:
- gesture navigation
- smart follow camera
- adaptive zoom
- notation focus modes

---

# 6. Current Architectural Priority

The current priority is:

> viewport architecture

NOT:
- renderer rewrite
- notation semantics expansion
- gameplay overlays
- advanced scoring systems

---

# 7. Success Criteria

Implementation is successful if:

- renderer output remains stable
- playback remains stable
- no semantic regressions occur
- no timing regressions occur
- notation readability improves significantly
- landscape mode becomes practical
- fullscreen practice becomes comfortable
- controls become less intrusive

---

# 8. Long-Term Direction

SightPlay should eventually feel closer to:
- a digital sheet music reader
- a piano practice workspace
- an immersive notation experience

rather than:
- a typical web application
